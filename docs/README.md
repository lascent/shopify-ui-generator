# Documentation

Project documentation is organized by purpose instead of development iteration numbers.

- `architecture/` — current system architecture and design intelligence
- `design/` — durable UI, layout, category, and storefront behavior notes
- `maintenance/` — stability and reliability fixes worth retaining as references
- `changelog/` — historical implementation notes and feature evolution
- `OPEN_SOURCE_CHECKLIST.md` — repository publishing checklist

Current implementation details should be documented by feature or subsystem name rather than by temporary development iteration.
